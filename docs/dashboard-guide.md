# 대시보드 가이드

jira-collector 는 두 종류의 대시보드를 제공합니다:

- **이슈 대시보드** (`/dashboards`) — 여러 Jira 서버의 이슈를 한 테이블에 모아 노트·트렌드·기간 보고서로 활용. 일상 운영용.
- **해결 시간 대시보드** (`/resolution-time`) — 여러 JQL의 **평균 해결 시간(Resolution Time)** 을 시간축·분포·슬로우 이슈 관점에서 비교 분석. 회고·개선용.

이 문서는 두 종류 모두의 활용법을 설명합니다.

---

## 0. 첫 사용자 흐름 (3분 요약)

1. **Jira 서버 등록** → `/settings/servers` 에서 PAT 또는 email+API token 으로 추가, "연결 테스트" 로 확인
2. **(선택) 커스텀 상태 정의** → `/settings/custom-statuses` 에서 "이슈 분석 중" 등 묶을 상태 등록
3. **이슈 대시보드 생성** → `/dashboards/new`, JQL 또는 URL 소스 입력 → 트렌드 차트 + 상태 통계 + 테이블 한 화면, 이슈 노트로 보고 메시지 누적
4. **(별개) 해결 시간 대시보드** → `/resolution-time/new`, 비교할 JQL을 라벨·컬러로 등록 → 평균 해결 시간 추이 + 분포 히스토그램 + 슬로우 이슈 분석
5. **(반복) 보고할 때마다** → 수동 새로고침 누르고, Markdown 으로 복사해서 슬랙/문서에 붙이기

## 1. Jira 서버 등록

`/settings/servers` → "서버 추가".

### Server/DC (사내 Jira)
- **Base URL**: `https://jira.corp.example.com` (trailing slash 없이)
- **인증 방식**: "Personal Access Token (Server/DC)"
- **PAT**: 본인 프로필 → Personal Access Tokens 에서 발급

### Atlassian Cloud
- **Base URL**: `https://<your-site>.atlassian.net`
- **인증 방식**: "Email + API Token (Cloud)"
- **이메일**: Atlassian 계정 이메일
- **API 토큰**: https://id.atlassian.com/manage-profile/security/api-tokens → "Create API token" → 즉시 복사 (한 번만 보임)

저장 전 **"연결 테스트"** 누르면 `/myself` 호출해서 인증된 사용자 이름이 표시됩니다. 토큰은 AES-256-GCM 으로 암호화되어 DB 에 저장돼요.

> 서버 여러 개를 동시에 등록할 수 있고, 대시보드마다 어떤 서버를 어떻게 섞을지 자유.

## 2. (선택) 커스텀 상태 정의

여러 서버의 상태명이 제각각일 때 통일해서 볼 수 있어요.

`/settings/custom-statuses` → "커스텀 상태 추가":
- **이름**: 예) "이슈 분석 중"
- **컬러**: 컬러 픽커로 선택 (예: #3B82F6 파랑)
- **매핑할 Jira 상태**: `In Progress`, `Resolved`, `진행 중`, `분석 중` 등 자유롭게 추가 (대소문자 무시)

> 한 Jira 상태는 **하나의 커스텀 상태에만** 매핑하는 것이 좋습니다 (여러 곳에 매핑되면 첫 매칭이 적용).

테이블의 상태 배지와 통계 바, 차트 모두 커스텀 상태를 반영해 표시합니다.

### 상태 컬러 오버라이드 (선택)

커스텀 상태 그룹을 만들지 않고 **원본 Jira 상태의 컬러만** 바꾸고 싶을 때:

`/settings/status-colors` → 상태 이름 + 컬러 등록. 우선순위는 **커스텀 상태 > 컬러 오버라이드 > Jira 카테고리 기본 컬러**.

## 3. 대시보드 생성

`/dashboards/new` 또는 사이드바의 `+` 버튼.

### 기본 정보
- **이름** (필수): 예) "내 보고용", "Sprint Review"
- **자동 새로고침 (초)**: 기본 300. `0` 으로 두면 자동 새로고침 비활성
- **설명** (선택)

### 소스 추가

각 소스는 `(서버, 타입, 내용)` 의 묶음. 여러 소스를 자유롭게 추가 가능.

**JQL 소스**
- **서버** 선택 + 타입 = `JQL 쿼리`
- 코드 폰트 textarea 에 JQL 입력
- **"쿼리 테스트"** 버튼으로 매칭 개수 미리 확인
  - 빈 JQL 이면 "JQL을 입력하세요" 표시되고 호출되지 않음
  - 에러는 Jira 응답 그대로 노출 (필드 오타·권한 등 디버깅 용이)

**URL 소스**
- 타입 = `이슈 URL 목록`
- 한 줄에 하나씩 URL 붙여넣기:
  ```
  https://jira.corp.example.com/browse/PROJ-101
  https://jira.corp.example.com/browse/PROJ-104
  ```
- 입력 즉시 각 URL 이 등록된 서버의 hostname 과 매칭되는지 검증, 매칭 안 되는 줄은 ✗ 표시

**여러 서버 혼합**: 같은 대시보드에 회사 Jira JQL + 오픈소스 Jira URL 목록을 함께 둘 수 있어요.

### JQL 작성 팁

자주 쓰는 패턴:

```jql
assignee = currentUser() AND statusCategory != Done ORDER BY priority DESC
project = "PROJ" AND updated >= -7d
project = PROJ AND labels = urgent AND status != Done
```

> Atlassian Cloud 는 2025 년 이후 `/rest/api/2/search` 가 제거됐고, jira-collector 는 자동으로 새 `/rest/api/3/search/jql` 엔드포인트를 사용합니다. JQL 문법 자체는 동일.

저장 → 자동으로 대시보드 뷰로 이동.

## 4. 대시보드 뷰

대시보드 한 화면에는 위에서 아래로 다음이 있습니다.

### (1) 트렌드 차트 (누적 burn-up)

- **파란 영역**: 누적 생성 이슈
- **초록 영역**: 누적 해결 이슈
- **두 영역의 간격 = 미해결 이슈 backlog**
- 상단에 `생성 N · 해결 M · 미해결 K` 요약 (미해결 0 이면 초록, 양수면 amber)

조작:
- **기간**: 14 / 30 / 60 / 90일 선택
- **높이**: 1x (140px) / 1.2x / 1.5x / 2x
- **숨기기/보이기** 토글 — 기간/높이/표시 여부 전부 `localStorage` 에 **대시보드별**로 저장

> **"해결"의 정의**: `resolutiondate` 가 우선. 없으면 status 카테고리가 `done` 인 이슈는 `updated` 일자를 사용. (Cloud 의 보드에서 Done 으로 드래그할 때 Resolution 필드가 비어있는 경우를 흡수)

### (2) 상태 통계 바

각 상태별 칩(이름 + 개수). **클릭하면 필터 토글**, 여러 개 멀티 선택 가능 (OR).
- "모두" 칩으로 한 번에 해제
- 우측에 활성 필터 있을 때 "필터 해제" 텍스트 링크 표시

### (3) 스마트 필터 · 분포 차트

트렌드/상태 바 아래 facet 필터 행:
- **내장 facet**: 상태 · 담당자 · 타입 · 우선순위 · 라벨 · 보고자 — 각 옵션 옆에 카운트 표시
- **커스텀 스마트 필터**: `/settings/smart-filters` 에서 정의한 facet(값마다 JQL)이 함께 노출됩니다. 필터가 참조하는 커스텀 필드(`cf[NNNNN]`)는 대시보드 로딩 시 자동으로 함께 불러옵니다
- facet 내부는 OR, facet 간은 AND. 선택은 `localStorage` 에 대시보드별 저장
- 필터 결과는 테이블·상태 통계 바·분포 차트(파이/막대)에 모두 반영
- **분포 차트의 분류 기준**으로 내장 차원(상태·담당자 등) 외에 **커스텀 스마트 필터**도 선택할 수 있습니다. 값마다 매칭 이슈 수를 세고(한 이슈가 여러 값에 매칭되면 각각 카운트), 어떤 값에도 안 걸리는 이슈는 `(해당 없음)` 으로 묶입니다

### (4) 컨트롤 바

- **이슈 검색** — 클라이언트 측 즉시 필터 (key, summary, 상태, 담당자, 보고자, 서버명, 노트, labels 검색)
- **마지막 갱신 시각** + 로딩 스피너
- **새로고침** — 강제 fetch
- **기간 보고서** — 아래 5번 섹션 참조
- **Markdown** — 화면에 보이는 컬럼/행을 GitHub-flavored markdown 표로 클립보드 복사
- **CSV** — 동일 범위를 `.csv` 다운로드
- **컬럼** — 가시성 토글 메뉴

### (5) 이슈 테이블

- **필수 컬럼**: Key, 상태, Summary, 내 메모
- **옵션 컬럼**: 최근 코멘트, 담당자, 보고자, 생성일, 수정일, 해결일, 우선순위, 이슈 타입, Labels, 서버
- **정렬**: 컬럼 헤더의 정렬 아이콘 클릭. 기본 정렬은 `updated DESC`.
- **컬럼 순서 변경**: 헤더에 마우스 올리면 좌측에 **grip 아이콘** 표시 → 잡아서 드래그. 즉시 화면 반영, 700ms 후 자동 저장.
- **이슈 새 탭 열기**: Key 셀의 외부 링크 아이콘
- **빈 셀**: `—` 로 표시

### (6) 페이지네이션

테이블 아래 푸터에서 한 화면에 표시할 행 수를 **10 / 30 / 60** 중 선택할 수 있어요 (기본 30). 첫/이전/다음/마지막 페이지 버튼과 `현재페이지 / 전체페이지` 표시가 함께 있고, 선택한 페이지 크기는 `localStorage` 에 **대시보드별로 저장**됩니다. 검색·상태 필터를 바꾸면 자동으로 첫 페이지로 돌아갑니다.

### (7) 이슈 노트 (가장 중요)

대시보드 목적 자체가 "여러 서버의 이슈에 사용자 메모를 붙여 보고용으로 활용" 하는 것.

- **셀 클릭** → 인라인 텍스트 편집기로 변환
- **자동 저장** — 500ms debounced + blur 시 즉시 저장
- **`Cmd/Ctrl + Enter`** — 저장 후 편집 종료
- **`Esc`** — 변경 취소
- 저장 상태가 우측 상단에 스피너 → ✓ 로 표시
- **노트는 `(대시보드, 서버, 이슈 키)` 단위**로 저장되므로, **같은 이슈가 두 대시보드에 있으면 노트는 별개**입니다 (보고 맥락마다 다른 메시지 가능).

## 5. 기간 보고서

특정 기간의 활동을 Markdown 보고서로 만들어 슬랙·문서에 붙여 넣을 때 쓰는 기능.

컨트롤 바 → **"기간 보고서"** 버튼 → 다이얼로그.

### 입력
- **시작일 / 종료일** 직접 선택, 또는 빠른 프리셋(7일 / 14일 / 30일 / 90일)
- **노트 포함** 체크박스 — 해제하면 보고서에서 "내 메모" 컬럼 제거 (대외용)

### 보고서 구성
1. **요약** — 기간 내 신규 생성 / 해결 / 기타 업데이트 / 기간 종료 시점 미해결 잔량 + 상태별 분포
2. **해결 완료** (resolved-in-range) — Markdown 표. 해결일 컬럼.
3. **신규 (진행 중)** (created-in-range 중 미해결) — 생성일 컬럼.
4. **기타 진행 변경** (updated-in-range, 위 두 카테고리 제외) — 수정일 컬럼.

### 출력
- **Markdown 복사** — 클립보드로
- **.md 다운로드** — `report-<대시보드>-<시작>_<종료>.md` 파일

### 주의
- 보고서는 **현재 대시보드에 로드된 이슈만** 분석합니다. JQL 이 `status != Done` 처럼 해결 이슈를 제외하고 있으면, 해당 기간에 해결된 이슈가 누락돼요. 전체 커버리지가 필요하면 보고용 별도 대시보드를 만들어 JQL을 `updated >= -90d` 처럼 넓게 두세요.
- "해결" 의 정의는 `resolutiondate` 우선, 없으면 status 카테고리가 `done` 인 이슈는 `updated` 일자를 사용 (트렌드 차트와 동일).

## 6. 해결 시간 대시보드 (Resolution Time)

이슈 대시보드가 "**지금 어떤 이슈들이 있는지**" 를 보는 도구라면, 해결 시간 대시보드는 "**우리 팀의 이슈가 평균적으로 얼마나 걸려서 해결되는지, 그 추세가 어떻게 변하는지, 오래 걸린 이슈는 무엇인지**" 를 보는 도구입니다. 회고·SLA·개선 미팅에 유용합니다.

`/resolution-time` 또는 사이드바의 "해결 시간" 섹션에서 접근.

### 6.1 핵심 개념

- **여러 JQL을 한 대시보드에서 비교**합니다. 예: "Team A 백엔드 이슈" vs "Team B 프론트엔드 이슈", "전체 버그" vs "전체 스토리".
- 각 JQL은 **라벨**과 **컬러**로 식별되고, 모든 차트에서 동일 컬러로 표시됩니다.
- **해결의 정의**는 이슈 대시보드와 동일: `resolutiondate` 우선, 없으면 status 카테고리가 `done` 인 이슈는 `updated` 일자를 사용.
- 해결 시간 = `resolved - created` (시간 단위).
- **해결된 이슈만** 분석 대상. JQL이 미해결 이슈를 포함해도 차트·통계는 해결된 부분만 사용.

### 6.2 대시보드 만들기

`/resolution-time/new`.

#### 기본 설정
- **이름**: 예) "팀별 평균 해결 시간 추적"
- **자동 새로고침 (초)**: 기본 600
- **시계열 윈도 (일)**: 30 / 60 / 90 / 180 / 365 — 차트의 X축 범위
- **시계열 단위**: 일 / 주 / 월 / **분기** — X축 버킷 크기
- **히스토그램 버킷 (시간)**: 기본 24 (= 1일 단위 빈). 이 단위는 **1주까지만** 적용되고, 그 이후 구간은 1주–2주 → 2주–1달 → 1달–3달 → 3달+ 로 자동 확장됩니다 (긴 꼬리가 한 빈에 뭉치지 않도록).

#### JQL (여러 개 추가)

각 JQL은 다음 항목으로 구성:
- **컬러** + **라벨** (예: "Team A — 백엔드")
- **Jira 서버**
- **JQL 쿼리** — "쿼리 테스트" 로 매칭 개수 즉시 확인
- **시간축 오프셋 (일)** — 이 JQL의 시계열을 지정한 일수만큼 이동(양수 = 미래로). 시작 시점이 다른 프로젝트끼리 같은 시간축에서 추이를 겹쳐 비교할 때 사용. 추이·미해결·처리량·비율 차트와 마일스톤에만 적용되고, 해결 시간 값 자체(요약·분포·슬로우 분석)는 그대로. 오프셋이 걸린 시리즈는 범례에 `(+30일 이동)` 처럼 표시
- **마일스톤** (선택, 6.4 참조)

> 💡 JQL에 `resolved >= -90d` 같은 조건을 함께 두면 fetch 범위가 줄어 빨라집니다.

### 6.3 대시보드 뷰

위에서 아래로:

#### (1) 컨트롤 바
윈도(일) · 시계열 단위(일/주/월/분기) · 히스토그램 버킷(시간) · 마지막 갱신 시각 · 새로고침. 설정 변경은 DB에 자동 저장 (700ms debounced).

#### (2) 요약 카드 (JQL별)
각 JQL의 상단 카드에:
- **평균** 해결 시간 (큰 숫자)
- **중앙값** · **P90** · **해결/전체** 비율

#### (3) 스마트 필터 (per-JQL)
> Rich Filter의 Smart Filter 패턴을 차용한 facet 필터.

각 JQL마다 다음 facet으로 데이터를 좁힐 수 있습니다 (각 facet 내부는 OR, facet 간은 AND):
- 상태 · 담당자 · 타입 · 우선순위 · 라벨 · 보고자

각 옵션 옆에 **카운트** 표시. 필터 선택은 `localStorage` 에 대시보드별로 저장되어 새로고침해도 유지. 모든 차트와 슬로우 이슈 분석이 필터 결과를 반영합니다.

#### (4) 평균 해결 시간 추이 (시계열 라인 차트)
- 모든 JQL이 **같은 X축** 위에 자신의 컬러 라인으로 표시
- Y축은 `formatHours()` 단위 (예: `36h`, `2.5d`)
- 마일스톤은 수직 대시 라인으로 함께 표시 (6.4 참조)
- 라인의 빈 구간은 해당 버킷에 해결된 이슈가 없음을 의미
- JQL에 **시간축 오프셋**이 설정돼 있으면 그 시리즈(와 마일스톤)가 지정한 일수만큼 이동해 그려지고, 범례 라벨에 `(+30일 이동)` 처럼 표시됩니다

#### (5) 해결 시간 분포 (히스토그램)
- 기본은 **"전체 (누적)"** 모드 — 모든 JQL이 빈마다 색상 segment로 stack
- 셀렉트에서 특정 JQL을 선택하면 그 소스의 막대만 표시
- **막대(또는 segment) 클릭** → 해당 JQL의 그 빈에 속한 이슈가 모달로 표시 (오래 걸린 이슈를 즉시 추적)
- **구간 단위** — 1주까지는 설정한 버킷 단위의 고정 폭, 그 이후는 1주–2주 / 2주–1달 / 1달–3달 / 3달+ 로 점점 넓어지는 구간

#### (6) 오래 걸린 이슈 분석 카드 (Long-tail)
회고에서 "왜 이 이슈들이 오래 걸렸지" 를 파고들 때 핵심.

- **임계값** (일) 입력 + 빠른 프리셋 (7 / 14 / 30 / 90)
- **소스 필터** — 전체 또는 특정 JQL만
- **정렬**: 느림 배율 / 해결 시간 / 해결일 / 우선순위
- **차원별 상위 분포** — 슬로우 이슈 집합 내에서 라벨/담당자/타입/우선순위/상태 상위 3개와 점유율. 예: "슬로우 이슈의 60%가 `payment` 라벨".
- **테이블** — Key, 소스, 요약, 상태, 우선순위, 담당자, 라벨, **해결 시간**, **느림 배율** (vs 모집단 중앙값, 5x↑ 빨강 / 3x↑ amber), **최근 코멘트**, 해결일
- **Markdown 복사** — 분석 doc/노션에 그대로 붙여넣을 수 있는 구조화된 출력 (요약 통계 + 차원 분포 + 이슈 표)

### 6.4 마일스톤

각 JQL마다 의미 있는 시점을 등록해 시계열 차트에 표시할 수 있습니다 (예: v2 릴리즈 일자, SLA 정책 변경 일자, 팀 개편 일자).

- 입력: **이름** + **날짜** (YYYY-MM-DD) — 편집 폼의 각 JQL 카드 안에 "마일스톤" 섹션에서 추가/삭제
- 표시: 시계열 차트에 **소스 컬러의 수직 대시 라인** + 라벨
- 같은 버킷에 여러 마일스톤이 떨어지면 라벨이 **수직으로 stagger** 되어 안 가려짐. 라인 색상도 dash 패턴이 어긋나 두 컬러가 모두 보임
- 현재 윈도 밖의 마일스톤은 자동 숨김

해석 팁: 마일스톤 이후 평균 해결 시간이 줄어들면 그 변경의 효과, 늘어나면 영향 검토 대상.

### 6.5 사용 시나리오

1. **회고 (스프린트/분기)** — 윈도 90일 + 주별 단위로 추세 확인 → 슬로우 분석 임계값 14일로 도출된 이슈에 대해 "왜 오래 걸렸는지" 원인 파고들기 → Markdown 복사로 회고 doc에 첨부
2. **SLA 모니터링** — 윈도 30일 + 일별 단위 + 임계값 7일 → 7일 초과 이슈의 우선순위 분포가 Medium 이상이면 트리아지 프로세스 점검
3. **팀 비교** — Team A / Team B JQL을 한 대시보드에 두고, 평균/P90이 크게 차이나는 버킷의 슬로우 이슈를 비교 → 프로세스/리뷰어 부하 차이 식별
4. **변경 효과 검증** — "리뷰 1인 의무화" 같은 정책 변경 시점을 마일스톤으로 찍고, 이후 추세가 좋아지는지 추적

> 데이터에 노이즈가 많을 때는 **중앙값**(median) 또는 **P90**을 기준으로 보세요. 평균은 한두 개 outlier에 크게 흔들립니다.

## 7. 대시보드 관리

### 목록 화면 (`/dashboards`)

- 카드 그리드, **즐겨찾기**(별)는 항상 위로
- 카드에 마우스 올리면 우하단에 액션 아이콘 — 편집 / 복제 / 삭제
- "새 대시보드" 우측 상단 버튼

### 복제

복제된 대시보드는 **소스 + 컬럼 설정**이 그대로 복사됩니다. **노트는 복사되지 않습니다** (원본 대시보드의 노트와 분리). 이름은 `… (복사)` 가 자동 부여.

### 삭제

`삭제` → 확인 → 대시보드 자체 + 소스 + **노트**가 cascade 로 함께 제거. 복구 불가하므로 신중히.

### 편집

`/dashboards/[id]/edit` 에서 이름·새로고침 주기·소스·설명 변경. 소스를 전부 비우고 저장하면 빈 대시보드(이전 노트는 남아있음 — 이슈가 다시 들어오면 노트도 복원돼 보임).

## 9. 자주 묻는 질문

**Q. JQL 결과가 너무 많아요. 잘리지 않나요?**
A. 기본 상한 1000 건. 그 이상이 필요하면 JQL 을 조건으로 좁히세요 (예: `updated >= -30d`).

**Q. 대시보드 자동 새로고침을 끄고 싶어요.**
A. 편집 화면에서 "자동 새로고침 (초)" 을 `0` 으로 저장.

**Q. 한 이슈에 노트를 여러 줄로 쓰고 싶어요.**
A. 가능. 노트 셀은 textarea (auto-grow), 줄바꿈 그대로 저장됩니다. Markdown 내보내기에서는 `/ ` 로 join 되니 보고용 출력은 한 줄로 합쳐집니다.

**Q. 컬럼 폭이 마음에 안 들어요.**
A. 현재 컬럼 폭 드래그 조절은 미지원. 컬럼 가시성 토글로 안 보이게 하거나 순서 변경으로 우선순위 조정 권장.

**Q. 코멘트 본문이 잘려요.**
A. 최근 코멘트 셀은 200자에서 잘립니다. 풀버전이 필요하면 Key 셀의 외부 링크로 Jira 열기.

**Q. Jira API rate limit 에 걸리진 않나요?**
A. Cloud 는 약 10 req/s 가 안전선. URL 모드로 동시에 많은 이슈를 가져오면 429 가 날 수 있어요. 같은 결과는 가능하면 **JQL 한 줄로 묶는 게** 호출 수가 적고 빠릅니다.

**Q. 두 대시보드 사이에서 노트를 공유하고 싶어요.**
A. 현재 노트는 대시보드별로 격리. 같은 메시지를 공유하려면 한 대시보드만 유지하고 카드 즐겨찾기로 빠르게 접근하는 방식이 현실적입니다.

**Q. 백업은 어떻게 하나요?**
A. `data/app.db` 파일 + `.env.local` (의 `APP_ENCRYPTION_KEY`) 둘을 같이 백업하세요. 자세한 운영은 [self-hosting.md](self-hosting.md) 참조.

### 해결 시간 대시보드 관련

**Q. 해결되지 않은 이슈도 차트에 보이나요?**
A. 보이지 않습니다. 시계열·히스토그램·슬로우 분석 모두 **해결된 이슈만** 대상입니다. 다만 "해결/전체" 비율과 스마트 필터의 facet 카운트는 미해결 포함 전체를 기준으로 합니다.

**Q. 같은 JQL인데 이슈 대시보드와 해결 시간 대시보드의 카운트가 다릅니다.**
A. 이슈 대시보드는 **모든 이슈**를 표시하지만, 해결 시간 대시보드의 통계는 **해결된 이슈만** 집계합니다. JQL 자체는 동일해도 분석 대상이 다릅니다.

**Q. 평균이 들쭉날쭉합니다. 더 안정적인 지표가 있나요?**
A. 요약 카드의 **중앙값(median)** 또는 **P90**을 보세요. 한두 개 outlier가 평균을 크게 흔들 수 있습니다. 시계열 차트 자체는 평균을 표시하지만, 시점별 outlier가 의심되면 그 버킷의 히스토그램·슬로우 분석으로 드릴다운하세요.

**Q. 마일스톤 라벨이 너무 많아 차트가 어지러워요.**
A. 윈도(일)를 조정해 표시 범위를 좁히면 윈도 밖 마일스톤이 자동 숨겨집니다. 또 마일스톤은 JQL별로 가지므로, 분석에 안 쓰는 JQL을 임시 제거하면 라벨이 줄어듭니다.

**Q. 슬로우 이슈 임계값은 어떻게 정하나요?**
A. 시작점은 **중앙값의 3배 또는 P90 근처**로 잡고, 차원별 분포에서 패턴이 드러날 때까지 조정합니다. 너무 작으면 노이즈가 많고, 너무 크면 outlier가 가려져요.

**Q. 해결 시간 대시보드도 자동 새로고침되나요?**
A. 예. 기본 600초(10분). 편집 화면에서 변경 가능 (`0` 으로 두면 비활성).
